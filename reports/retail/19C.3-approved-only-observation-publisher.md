# Sprint 19C.3 — Approved-Only Observation Publisher

## Status

✅ Complete and verified.

## Purpose

Sprint 19C.3 hardened the retail observation publisher so staged retail observations can no longer bypass the Admin Review workflow.

The required publishing path is now:

staged observation → Admin Retail Review approval → approved-only publisher dry run → controlled apply → shopper-facing product update

## Change Made

The script:

- `scripts/retail/publish-staged-observations.mjs`

was changed so that it only publishes observations where:

- `review_status = approved`

The older bypass flag:

- `--approve-pending`

is now blocked.

If used, it exits with:

- `ERROR: --approve-pending is no longer allowed.`
- `Retail observations must be reviewed in Admin → Retail Review before publishing.`
- `Use review_status='approved' as the publishing gate.`

## Governance Outcome

MallMind now has a hardened retail data governance path:

1. Raw/manual retail data enters staging.
2. Admin reviews staged observations.
3. Only approved observations are visible to the publisher.
4. Pending and needs_more_info rows cannot be published.
5. The old pending bypass is blocked.
6. Publishing remains dry-run by default and requires explicit `--apply`.

## Current Limitation

The publisher can still mark `manual_fact_entry` rows as `manually_verified` once approved.

That is acceptable for current controlled admin use, but the next hardening sprint should split product quality more carefully, for example:

- `admin_approved_manual`
- `externally_verified`
- `retailer_confirmed`
- `live_feed`
