# Sprint 19C.7 — Retail Intelligence Core v1

## Status

Complete.

## Purpose

Sprint 19C.7 consolidated MallMind's retail data safety logic into a shared Retail Intelligence Core.

Before this sprint, retail matching, trust mapping, preview planning, and warning logic were duplicated across scripts and backend routes.

This sprint created one shared retail brain for:

- product matching
- trust mapping
- verification-method mapping
- publish planning
- warning generation
- ambiguous-match refusal

## Why This Matters

MallMind's retail data pipeline must be extremely trustworthy.

The system must never accidentally:

- publish weak manual CSV data as verified
- silently choose the wrong product during matching
- let admin preview and publisher disagree
- expose internal data states to shoppers
- publish anything without explicit approval

The Retail Intelligence Core reduces drift by making publisher, linker, and admin preview use the same decision logic.

## Core Retail Spine

The current retail spine is:

source → snapshot → retail observation → product_id match → admin review → publish preview → controlled publisher → products table → shopper recommendation

### 2. Product Matching Centralized

Matching now follows one shared rule:

1. Prefer `retail_price_observations.product_id`
2. Fall back to `shop_id + normalized product_name`
3. If no match, return `insert_new`
4. If multiple name matches exist, return `ambiguous`

Ambiguous matches are no longer silently resolved.

### 3. Ambiguous Match Safety

Previous risk:

- the preview/publisher could silently select one product if duplicate shop/name matches existed.

New behaviour:

- ambiguous rows are detected
- ambiguous candidate IDs are surfaced
- publisher does not automatically publish ambiguous rows
- ambiguous rows are skipped/refused for apply

This is a trust-tightening change.

### 4. Trust Mapping Centralized

The 19C.4 hardening rule is now centralized:

`manual_fact_entry + csv_manual → needs_review`

This prevents weak manual CSV/admin-entered rows from becoming verified shopper-facing prices.

Evidence-backed methods such as:

- phone
- website
- flyer
- receipt
- store_visit
- retailer_confirmation
- scraper
- retailer_api

may map to verified quality when paired with trusted states.

### 5. Verification Method Mapping Centralized

The publisher's method mapping is now shared:

- `phone` passes through
- `website` passes through
- `csv_manual` maps to null for products
- `affiliate_feed` maps to `retailer_api`
- `partner_feed` maps to `retailer_api`
- unknown methods map to null

### 6. Warnings Centralized

Warning generation is now shared.

Warnings include:

- Manual CSV/admin-entered row will publish as needs_review, not Verified price.
- Verification method `csv_manual` is not external evidence-backed.
- Confidence is low; consider stronger evidence before publishing.
- Ambiguous product match detected; manual review required.
