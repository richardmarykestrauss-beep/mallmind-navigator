# Sprint 19C.2 — Admin Retail Observation Review UI

## Status

✅ Complete and verified end-to-end.

## Purpose

Sprint 19C.2 added an admin-facing review workflow for staged retail price observations.

Before this sprint, staged retail observations could be imported and published through scripts, but admin review still required direct script/database workflows.

This sprint adds the missing governance layer:

staged retail observation → admin review queue → approve / reject / needs_more_info → later controlled publish

Publishing remains separate and controlled.

## Delivered

### Backend

Added a protected Cloud Run admin route:

- `GET /admin/retail-observations`
- `POST /admin/retail-observations/:id/review`

The route:

- requires an authenticated Supabase admin bearer token
- checks `profiles.is_admin`
- returns staged retail observations with shop/source/snapshot context
- updates `review_status`
- records `reviewed_by`, `reviewed_at`, and `review_note`
- blocks review changes to already published rows
- does not publish live products

Committed as:

- `d3b376a feat(retail-data): add admin retail observation review route`

### Frontend API Client

Added typed frontend helpers:

- `getRetailObservationsAdmin`
- `reviewRetailObservation`

Committed as:

- `6213b8a feat(retail-data): add retail observation admin client helpers`

### Admin UI

Added a new Admin Dashboard tab:

- `Retail Review`

The UI shows:

- pending staged retail observations
- product name, price, shop, unit/floor
- trust state
- verification method
- confidence
- source and snapshot provenance
- review note
- action buttons:
  - More Info
  - Reject
  - Approve

The UI clearly states that review does not publish to live products.

Committed as:

- `29bfb12 feat(retail-data): add admin retail observation review tab`

## Product Governance Boundary

19C.2 intentionally does not publish approved observations automatically.

Correct future workflow:

1. Import/stage observations.
2. Admin reviews rows in Retail Review.
3. Verified rows can be approved.
4. Controlled publisher script publishes approved rows.
5. Shopper-facing product records update only through controlled publish.
