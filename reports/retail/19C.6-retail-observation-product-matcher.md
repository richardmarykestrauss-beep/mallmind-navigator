# Sprint 19C.6 — Retail Observation Product Matcher

## Status

Checkpoint complete.

## Purpose

Sprint 19C.6 added a safe product-linking layer between staged retail observations and existing products.

The purpose is to connect staged retail observations to their matching product records before admin review and publishing.

This strengthens the retail data spine:

source → snapshot → retail observation → product_id link → admin review → publish preview → controlled publisher → products table → shopper recommendation

## Why This Matters

Before this sprint, product matching happened late in the publisher and admin preview logic by using:

shop_id + normalized product_name

That worked, but the observation itself did not clearly store its product relationship until publish time.

This made the data pipeline weaker because admin review could not clearly distinguish:

- an observation that updates an existing product
- an observation that inserts a new product
- an observation that has no safe match
- an observation that has an ambiguous match

Sprint 19C.6 adds the missing bridge.

### 3. Product Linker Script

Added:

`scripts/retail/link-observations-to-products.mjs`

The script is dry-run first.

It matches observations to products using:

mall_id + shop_id + normalized product_name

The script only writes:

`retail_price_observations.product_id`

It does not:

- publish products
- change review_status
- change published_product_id
- update product prices
- modify product quality
- approve or reject observations

### 4. Product Links Applied

- publishable_approved_unpublished_count: 0

All 10 observations now have `product_id` populated.

### 5. Publisher Updated

Updated:

`scripts/retail/publish-staged-observations.mjs`

Publisher matching now follows:

1. Prefer `retail_price_observations.product_id`
2. Fall back to `shop_id + normalized product_name`
3. Insert new product only if no linked or name-matched product exists

Publisher remains gated by:

`review_status = approved`

Dry-run after patch confirmed:

- publishable observations: 0
- Nothing to publish

### 6. Admin Publish Preview Updated

Updated:

`google-cloud-backend/src/routes/retailObservationsAdmin.ts`

Admin publish preview now follows the same matching strategy:

1. Prefer `product_id`
2. Fall back to shop/name match
3. Else mark as insert_new

The preview now returns `match_strategy`, allowing future UI/reporting to explain how each observation will publish.
