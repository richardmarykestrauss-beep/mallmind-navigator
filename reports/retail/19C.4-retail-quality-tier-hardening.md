# Sprint 19C.4 — Retail Quality Tier Hardening

## Status

✅ Complete and verified.

## Purpose

Sprint 19C.4 hardened MallMind's retail trust model so admin-approved manual observations do not automatically become shopper-facing "Verified price" products.

Before this sprint, the publisher mapped:

- `manual_fact_entry` → `manually_verified`

That was too broad. A manually entered CSV row can be admin-approved for controlled publishing, but that does not always mean the price was independently verified by phone, website, receipt, store visit, retailer confirmation, flyer, scraper, or API.

## Change Made

Updated:

- `scripts/retail/publish-staged-observations.mjs`

The publisher now maps product quality using both:

- `trust_state`
- `verification_method`

New rule:

- `manual_fact_entry + csv_manual` → `needs_review`
- `manual_fact_entry + evidence-backed method` → `manually_verified`
- `verified / retailer_submitted / flyer_extracted / web_observed` → `manually_verified`
- `live_feed` → `live_feed`
- `user_submitted` → `user_submitted`
- `expired / stale / disputed / needs_review` → `needs_review`

Evidence-backed methods are:

- `phone`
- `website`
- `flyer`
- `receipt`
- `store_visit`
- `retailer_confirmation`
- `scraper`
- `retailer_api`

## Governance Outcome

MallMind's retail data pipeline now separates:

- admin approval
- product publishability
- shopper-facing verification language

This prevents the system from overclaiming price certainty.

An admin can approve a manual row for controlled publishing, but if the row lacks external evidence, it publishes as `needs_review`, not `manually_verified`.

## Current Trust Boundary

The two already-published retail observations remain high-trust:

- Hisense 43" FHD LED TV — phone verified
- Woolworths Greek Yoghurt 500g — website verified

Manual CSV observations remain staged or needs-more-info until better evidence exists.
