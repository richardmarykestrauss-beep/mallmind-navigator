## Test 1 — Product Query

Query:

`I need a TV under R4000`

Request context:

- mall_id: Mall@Reds seed mall
- mall_name: Mall@Reds
- budget: 4000
- session_id: null
- user_id: null

Result:

- `POST /assistant` succeeded
- `product_count`: 3
- `shopping_answer`: present
- `shopping_answer.intent`: `budget_search`
- `bestOption`: Hisense 43" FHD LED TV
- `bestOption.price`: R3499
- `bestOption.trustLabel`: Verified option
- `bestOption.confidenceBand`: high
- `backupOption`: Samsung 32" HD Smart TV
- `backupOption.trustLabel`: Example/demo data
- `nextAction.type`: compare
- `shopperMessage`: safe shopper-facing response

## Product Query Safety Observations

The structured `shopping_answer.shopperMessage`:

- did not expose internal raw statuses
- did not claim stock
- did not invent a route
- did not invent a price
- clearly distinguished verified best option from weaker backup option
- did not show internal states such as `manual_fact_entry`, `csv_manual`, or `needs_review`

The legacy Gemini `message` was weak:

`What else can I help you find?`

This confirms the next frontend step should display `shopping_answer` as the trusted recommendation card rather than relying only on Gemini free-text.

## Test 2 — Route Query

Query:

`Take me to Game`

Request context:

- mall_id: Mall@Reds seed mall
- mall_name: Mall@Reds
- session_id: null
- user_id: null

Result:

- `POST /assistant` succeeded
- Game was found
- Floor/unit returned: Floor G · Unit Shop G01
- `build_route`: true
- `route_shop_ids`: Game shop id
- `route_summary`: 1 stop · ~1 min walk
- `route_steps`: 3 steps returned
- `route_id`: null, expected because no session_id was provided
- `shopping_answer`: null, expected for pure store-route request

## Route Query Safety Observations

The assistant:

- did not hallucinate products
- did not claim a product price
- did not apologize about missing session
- returned concrete route steps
- gave a clear route-ready message
- correctly handled no-session routing without persisting a route_id
